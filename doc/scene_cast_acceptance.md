## Native and CI qualification

`toonzlib/tests/castworkflow_test.cpp` is registered as the required `castworkflow` CTest and included in Linux, Windows and macOS regression manifests. It uses native scene/level serialization, nested shared xsheets, stale paths, cycles, budgets, cancellation, Unicode tags and soundtrack replacement.

`toonz/castworkflowintegrationtest.cpp` runs inside the existing disposable-profile OpenToonz native UI qualification process. It drives actual controls and modal dialogs, with deadlines to turn missed dialog automation into a reported failure. The native application hook is enabled on all three OS workflows. macOS now records and annotates native application failures and uploads the output alongside regression evidence.

Ownership transition checks also save and reopen native scenes after relinking,
undoing the relink, making a local copy, undoing the copy and redoing it. They
require exact provenance, relationship, stable UUID, expected-source state and
resolved path, then decode the saved asset and compare its pixel content. The
synthetic attribution uses the supported `rig` item kind; raster is the asset
type, not a Library item kind. These checks are prepared for CI, not locally
executed.

Pending CI checks: compile/link on all platforms; the required `castworkflow` test; the native application workflow; unchanged existing native/regression suites. Prepared tests are not reported as executed or passing. Manual acceptance remains necessary for actual audio devices, accessibility/screen-reader behavior, very large network-mounted casts, and diverse collected production projects on a second machine. The synthetic relocated-project workflow is already prepared as a required native CI oracle.

## File and cancellation rules

- Cast modal workflows share the original panel's lifetime and scene scope.
  Hiding or destroying that panel (or an ancestor), or switching scenes,
  permanently invalidates the open operation, including nested file choosers,
  overwrite prompts and confirmations. Stack dialogs and caller-owned context
  menus have nonowning native transient relationships, so panel deletion cannot
  delete their storage before their event loops return. No late queued action
  may navigate, publish files or add Undo after invalidation. A new invocation
  gets a fresh scope. User-canceled read-only progress can still show a partial
  report; owner or scene invalidation does not open another report.
- `castinterruptionintegrationtest.cpp` prepares native owner-hide, destruction,
  ancestor-hide and New Scene interruptions, with actual queued controls and
  exact asset identity/content, collections, nested exposure, history, dirty
  state and file snapshots. It covers nested relink/local-copy/consolidation/
  report prompts, an existing CSV overwrite, and fresh repeated tag edits.
  Folder deletion revalidates the reviewed hierarchy and resolves tree items
  again after its confirmation; a refresh while that prompt is open is covered.
  These are new source-level safeguards and prepared CI assertions for reopened
  items 39, 40, 42, 43, 46–48 and 50–52, not evidence of an executed crash or of
  successful qualification of this revision. Earlier passing runs precede these
  changes.
- [Linux candidate 9629a7c5](https://github.com/OpenAnimationLibrary/groundzero/actions/runs/41092545441)
  reached the folder interruption cases and exposed a stale global folder-tree
  selection: selecting the next tree entered a destroyed selection's virtual
  method. `CastTreeViewer` now detaches before its selection base is destroyed,
  blocks teardown signals from registering it again, and the browser detaches
  it while its model is still alive. The added native regression destroys
  actually current trees and selects replacements without clearing selection
  in the fixture. The existing interruption cases remain. This correction is
  prepared for fresh CI, not qualified by the earlier run.
- [Linux candidate 5d02222bf8](https://github.com/OpenAnimationLibrary/groundzero/actions/runs/41101342783)
  advanced through those interruption boundaries, then failed the combined
  fresh-tag value/one-Undo assertion. That log does not identify which field
  differed. Source tracing independently found that a selected scene-root
  label update could enter the folder-rename handler and add a phantom Undo
  during the tag edit's dirty notification. Root display updates now block
  edit signals, and folder edits require an editable, existing, nonempty
  folder path. Native coverage retains the fresh-tag, Cancel and exact Undo
  checks, adds bounded acceptance/history diagnostics, and checks selected
  visible and hidden roots against full folder/membership/history snapshots.
  The existing real-folder rename/Undo checks remain. Fresh CI must establish
  the runtime outcome of this correction.
- Search, preview navigation, read-only inspection and reports do not alter level data or exposure cells. Explicit cover selection and confirmed consolidation are undoable edits. Native child navigation may add its normal navigation undo records.
- Relink and local-copy preparation does not alter live paths. All chosen assets validate before one grouped application. Cancellation during snapshotting or streamed copying discards the prepared operation.
- A published local-copy directory is user data. Undo never deletes it; subsequent redo uses that exact directory. No source or existing destination file is overwritten or deleted.
- Tags, cover choices and Library origin belong to levels; membership uses stable asset UUIDs, not names or paths. Two cast levels pointing to one file can have different tags and covers. Confirmed consolidation combines tags (and rejects a group exceeding 32 tags), retaining the chosen canonical cover. The tag editor replaces the tag set for each selected level; it is not an additive merge.
- Usage budgets default to 2 million inspected cells, 10 thousand occurrence rows/instances and depth 64. Incomplete results are labeled; unused removal requires a complete acyclic index.
- Reports describe discovered dependencies, not proof that an external tool can open every dependency or that two differently configured levels are interchangeable.
